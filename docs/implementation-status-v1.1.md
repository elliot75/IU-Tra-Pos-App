## 2. 測試證據的解讀

`test-support/operations-db.js` 使用 `@electric-sql/pglite`，在隔離資料庫執行 `001/002/004`。PGlite 是真實 PostgreSQL 引擎，不是只比對 SQL 字串的 mock；可驗證 DDL、外鍵／CHECK／唯一鍵／觸發器、交易提交／回滾與 SQL 相容路徑。營運測試涵蓋收現金、銀行去重／晚到、錢包、退款保留、列印狀態、門市 scope，以及提交後回應丟失、寫帳本失敗等注入情境。

轉接器以單一 PGlite 連線序列化每筆交易。測試中的 `Promise.all`／`Promise.allSettled` 可以驗證依序競逐後的業務結果，但不會產生原生 PostgreSQL 多連線行鎖排程、真實 deadlock、隔離級別交錯或部署連線池行為，不能作為 AT-10／AT-14 原生併發通過證據。既有商品與登入測試另使用模擬連線，亦不能與引擎驗證混稱。

`test/backup-pos.test.js` 的加密封裝／staging、錯 key／竄改測試，不代表真 DB `pg_dump/pg_restore` 或完整還原已演練。`test/operations-ui.test.js` 的待確認 journal／請求／購物車邏輯驗證，不等於完整瀏覽器點擊、實體客顯或收銀全流程。2026-11-06 本次整合在 main 的未提交變更執行完整 `npm test`：133 項通過、0 失敗、0 跳過；新增受限資料庫角色測試驗證鎖定函式的明確 EXECUTE 授權、可開班與防止更新授權／改寫財務／truncate／停用觸發器。瀏覽器已驗證合成現金交易、主屏及工作台重整後完成原單、主屏解鎖及內部備註不洩漏。瀏覽器使用既有隔離 demo 程序，因此最新後端恢復與鎖定函式以獨立 PGlite 測試為準。沒有執行真實營運 DB migration、configure apply、pg_dump 或完整還原。

## 4. 試點前仍須完成

1. 核對 T-01／03／04／05／06／07／08／09／13／14 的實際政策，明確決定納入的銀行、儲值、退款、責任與交接、語言、異常處置及必要發票。不以 configure 範例值代替營運核准。
