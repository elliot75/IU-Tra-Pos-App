# IUTRA POS

依《IUTRA POS 系統規格書 v1.0》開發中。目前提供商品草稿與菜單發布、點餐小結及伺服器端計價的開發版本，尚不能用於正式營業或收款。

## 啟動

需要 Node.js 22 以上，先安裝套件：

```bash
npm install
```

將 `.env.example` 複製成 `.env`，依自己的開發環境填寫。啟動：

```bash
npm run dev
```

在 `http://127.0.0.1:3000` 開啟點餐畫面，`http://127.0.0.1:3000/admin` 為商品管理。預設僅本機可存取；目前管理權杖只是開發階段的共用憑證，尚無具名帳號、角色授權或稽核，不可將此服務公開至網路。

執行測試：

```bash
npm test
```

## PostgreSQL 與初始化

在 `.env` 自行設定 `DATABASE_URL` 與長且隨機的 `ADMIN_API_TOKEN`，不要提交 `.env` 或將密碼寫入文件。跨網路資料庫連線應使用經驗證的 TLS，依資料庫供應商指示設定連線字串與 CA。`GET /api/v1/health` 僅執行 `SELECT 1`，顯示連線狀態，不會檢查菜單資料表是否已初始化。

應用程式啟動時不會自動建立或修改資料庫。[migrations/001_catalog.sql](migrations/001_catalog.sql) 是供審閱後手動執行的全新安裝 SQL，會建立 `iutra_pos` schema、草稿及發布快照表；如果同名 schema 已存在，會報錯而不覆寫。執行前須確認目標、盤點既有 schema、備份並取得變更權限，先在獨立的開發／測試資料庫驗證；既有結構需要映射時不要直接套用。SQL、真實 PostgreSQL 交易和並行鎖定尚未經實機驗證。正式部署還須區分應用與遷移帳號並配置最小權限。

設定並初始化後，在商品管理頁輸入管理權杖，新增分類、商品、容量和配料，先儲存草稿再發布。草稿有版本衝突時需重新載入；發布快照不會因後續草稿改動而變更。點餐畫面載入目前已發布版本；若資料庫未設定或沒有發布版本，會顯示提示，只有主動選擇才會載入範例菜單。

## 目前功能與限制

- 菜單目前是全系統單一草稿及發布版本，尚未支援門市、啟用排程、停售、甜度冰量或商品圖片設定；分類及商品名稱目前須輸入中越文，正式語言政策仍待確認。
- 伺服器使用整數 VND 計價，API 金額使用十進位字串；菜單版本不符時拒絕試算，不採信瀏覽器傳入的價格。
- 規格範例：烏龍茶 500 ml 22,000₫、700 ml 24,000₫；示範配料 5,000₫。配料名稱及上限僅供測試，並非正式菜單。
- 訂單只存於瀏覽器記憶體，重新整理即清除；試算不是正式訂單或財務交易。尚未實作訂單持久化、員工驗證、班次、客顯、收付款、會員儲值、退款、離線同步及設備整合。
- 自動測試中的商品資料庫測試使用模擬連線，不能視為 PostgreSQL 整合或併發測試。設備、銀行及資料庫既有結構仍須依規格驗證。
